# Keel 0.2.2 development slices

Local development starts from published Keel v0.2.1, commit `87bcaff`. The test target is Starship EVO Steam build 26451593 / 26w45a on Unity 6000.6.6f1. The dedicated Keel 0.2.2 lab starts with the published 0.2.1 runtime and a separate LocalLow profile.

## First slice

Static inspection traced native `PlanetGravityData.atmosphereDensity` to `SolarBody.SetPhysicsData` and found the native radius-based falloff. The stock wind turbine helper walks gravity rows and can overwrite a prior row's result. A reusable query must resolve the requested body explicitly before reading density. The native wind result is a scalar density input, so the vector velocity contract still needs a defined provider source and coordinate frame.

The first implementation is an experimental read-only density sampler. In a managed disposable solo profile, enable `EnableAtmosphereSampling` or set `SEVO_KEEL_EXPERIMENTAL_ATMOSPHERE_SAMPLING=1`. Call `AtmosphereSampling.SampleDensity` with a `BodyEnvironmentTarget` and a body-local position in metres. It reads the loaded body's indexed gravity row on the main thread during a native-container-safe phase and checks the row's body and transform IDs before invoking the stock falloff. The result is in stock relative units. A successful vacuum sample has zero density. A missing or unloaded body returns `BodyUnavailable`.

## Local implementation status

- **Atmosphere and weather fields.** `AtmosphereProviders.Register` accepts one provider per seeded body. `AtmosphereSampling.Sample` and `SampleSystemPosition` pass body-local metres, stock relative density, and caller-supplied simulation seconds to that provider. Consumers of the same field must supply the same clock. Air velocity is body-relative metres per second. Stock and declined samples report unknown velocity. With `EnableAtmosphereObservers`, a mod can register a location and receiver for local visual or audio effects, and clear them when it receives a null sample. Mods own weather state, presentation and clock persistence. Stock cloud, fog, precipitation and audio rendering have no Keel bindings in this candidate.
- **Drag and heating.** With `EnableGridPointMotion` and grid physics, `GridForceService.TryReadPointMotion` reads native world-frame velocity at a grid-local point, including rotation. `TryApplyAtmosphericDrag` applies a bounded force through the existing physics callback. `AtmosphericHeating.TryCalculateEnergy` supplies bounded energy to a mod-owned thermal model. The mod supplies world-frame air velocity, exposed area and calibration. Stock damage and native exposed-area discovery remain outside these hooks.
- **Terrain anchors.** Enable `EnableTerrainAnchors` and the world surface query. `TerrainAnchor.Capture` returns a body-relative position and normal. `Resolve` checks a fresh collider and fails while the body or surface is missing. With `EnableTerrainAnchorAttachments`, mods can attach, restore and release a namespaced pose bound to a stock-saved player grid in the current character and world. A live attachment revalidates before applying compression-only suspension through grid physics. This is a mod-owned suspension binding. Stock gear lock state is independent.
- **Persistent waypoints.** Enable `EnablePersistentWaypoints` and navigation markers. `PersistentWaypoints` provides atomic upsert and deletion scoped to the managed profile, character and world seed. It resolves system, rocky-body or persistent grid anchors. `EnablePersistentWaypointMap` draws Keel-owned selectable pins in the native Orrery and exposes the current pick via `PersistentWaypointMap.TryGetSelected`. Stock tracking IDs retain their own selection path. Flat-map pins and stock warp/autopilot binding are outside this integration.
- **Stock wreck claims.** Enable both `EnableWreckClaim` and `EnableStockWreckClaim`. `TryClaimStockTerrainWreck` transfers an eligible loaded terrain wreck to a caller-provided clear-space pose, retaining its persistent ID. Keel journals the stock source and replacement, and protects retired nodes against fresh generation and saved-node respawn. A profile with retirement state requires protection even when new claims are disabled. In-game interruption and reload acceptance remain open.
- **Connected rails.** Enable mechanism paths, `EnableConnectedRails`, and `EnableStockRailTools`. `TryDiscoverStockStraightRail` reads the linked straight extension chains. `MechanismPath.FromConnectedRail` accepts authored 90-degree joins because this build has no stock corner piece. `RegisterConnectedRail` preserves the stock home position and uses a caller sweep or the conservative stock collision-bounds sweep. Bounds can reject some clear routes. Live extension travel, collision and reload remain open.
- **Asteroid grading.** Enable `EnableAsteroidTerrainEdits` in addition to terrain edits and world surface queries. The existing planar brush can use a resident unbaked asteroid with a verified transform and tree, unit scale and stock save eligibility. `ApplyPlaneFillWithMaterial` assigns a live registered material to samples that become solid. Existing solid samples retain their material. The separate audit checks the asteroid save flag and reload admission path. Baked or empty chunks remain outside this preview.

Stock `OnVoxelDataLoaded` allocates a density slot and marks the node as loaded from disk. Using it to synthesize a solid region would change the stock save-origin semantics. Empty-chunk creation needs its own audited coordinate selection, allocation rollback, geometry publication and save roundtrip.

## Isolated runtime evidence

- Live density and vacuum checks passed in two fresh solo processes on Steam build 26451593 / 26w45a. Both selected star seed `6537562446814301439` and body seed `90`. The near-surface relative density was about 0.7756 at 1.01 times nominal radius. The vacuum sample was zero at twice nominal radius. An unknown body and an invalid position were rejected. This is one distinct body.
- A test provider halved stock density at an explicit sample time and supplied a body-local velocity of one metre per second. A different time returned stock density and unknown velocity. The probe checked both results in-game.
- A body-relative waypoint was written and resolved in solo character `Atmosphere-6afb32`. A separate process loaded the same character via the stock save loader, resolved the same integer system coordinates, deleted the waypoint, and read back the deletion. System and grid anchors remain outside this runtime evidence.
- The solo runs used a lab-only recovery diagnostic for a stalled native frame completion phase. It is absent from the candidate runtime.
- The target build admitted the connected-rail hook. Automated checks verified the negative extension offset, home position, and rejection of native extension arithmetic drift. Live extension travel and reload are still open.
- In isolated run `1b6f333c7a2c45fb83cfdfd9ec7c12b4`, a planet contact resolved before the cut and returned `SurfaceMissing` while rebuild was queued and after the new collider published. The cut removed 22 solid samples. The fill created 18 solid samples, all carrying the declared material in both packed channels. The fixture also checked that all other material IDs stayed unchanged and that the fill rebuilt collision. This run did not exercise grid suspension, asteroid editing, or reload of the custom fill.
- Integrated startup run `21f9283af4d54be7b2d5574996eefa00` admitted system-position atmosphere sampling, observers, saved terrain anchor attachments, asteroid grading, waypoint map pins, grid point motion, stock rail tools, and stock wreck claims. Startup admission checks hook installation and does not exercise those gameplay paths.
- Solo run `7a1e3ef70ba3414f8ab97b1f408c8168` observed two system-position samples at relative density 0.7756 and one exit notification after the observer withdrew its point. The fixture used the same body as the earlier density check.
- Solo run `831d9124bdd347fb9d0ca1d1c7e781ad` read native velocity at a point on a stock fixture grid, applied drag with a controlled relative air velocity, and observed an increase from 0 to about 0.115 m/s along the test axis. It did not exercise a powered ship, heating, or a second body's moving atmosphere.
